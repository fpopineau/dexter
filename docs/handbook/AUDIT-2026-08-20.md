A second external audit (broader than 2026-08-06: ledger analysis, backtester,
broker state machine, EOD policy, scorer statistics) was verified claim-by-claim
by four independent review passes plus a direct read-only re-query of
`proposals.db`. STATUS: F=fixed same day, B=backlog, D=disputed/overstated,
K=known (already triaged 2026-08-06, unchanged). Fix before live: every B

yet strong enough for live — is adopted.

## Criticals

1. F Concurrency slot counting was doubly wrong: (a) the accept path counted
   the row it had just claimed against its own caps (practical
   max_open_positions/max_daily_trades one below configured); (b) the
   'executing' term recorded as fixed in audit 2026-08-06 finding 5 was
   INERT — executing rows have `executed_at = NULL`, and `NULL >= n` is
   never true, so two concurrent accepts could share the last daily slot.
   Fixed: status-based counting for executing rows + `excludeId` on both
   counters; regression tests. (2026-08-20)
2. F Daily-loss halt and NetLiq baseline now latch IN MEMORY when the file
   write fails (closes 2026-08-06 finding 7). The baseline leg was worse
   than recorded: a failed write caused re-capture of the already-degraded
   NetLiq, resetting the P&L proxy to ~0 — the kill-switch could then NEVER
   trip. Residual (accepted): a restart with an unwritable data dir still
   loses the latch. (2026-08-20)
3. F `assertAccountsVerified` refusal on an empty managed-account list is
   now UNCONDITIONAL — `IBKR_ALLOW_LIVE=true` no longer waives identity
   verification (closes 2026-08-06 finding 3B). Note: with no accounts the
   profile stayed 'paper', whose count caps (10 positions / 20 trades) are
   LOOSER than live — the waiver was doubly unsafe. (2026-08-20)
4. F `closePosition` post-close was a naked-position generator: the DAY MKT
   close is a guaranteed IBKR 201 rejection after hours, but the flow
   cancelled the tracked bracket exits anyway and told the operator the
   order "waits for the open". Now refused outside REGULAR/PRE_MARKET (the
   position keeps its protection); the failure path also clears the
   `recentlyClosed` marker, which used to suppress auto-protect for 10
   minutes on a position whose close had FAILED. (2026-08-20)
5. F Half-days: EOD triage was hard-coded to 15:52 ET while DAY brackets
   die at the 13:00 close — and the tracker's `afterBell` (>=15:55) test
   classified 13:00 expiries as terminal closes, so the EOD-keep transition
   never fired: positions sat NAKED ~3h, then triage triaged a dead session.
   Fixed: 12:52 half-day cron slot (slots yield by calendar), catch-up
   window parameterized by the real close, `afterBell` derived from
   `isMarketHalfDay`. (2026-08-20)
6. B Broker-confirmed order state machine. Bracket placement returns on
   API handoff (no openOrder/orderStatus/error await — the docstring says
   so), the row is marked 'executed' immediately, and "The entry order is
   now WORKING" is asserted unverified. Mitigation exists (tracker
   self-heals rejections to 'cancelled' within seconds) but the window
   consumes a position slot and misinforms the operator. Needs: await
   first ack, `orderRef` idempotency key, `permId` persistence,
   `order.account` on EVERY order (bracket, protect, close, reduce-only),
   reverse reconciliation that ADOPTS unknown broker orders/positions
   (today reconcile is strictly DB→broker; unknown positions grant free
   cap headroom). [LIVE-GATE]
7. B Partial fills. Entry recorded only on complete fill; terminal partial
   → 'cancelled', P&L 0, position real but unaccounted (two such rows in
   the DB). The fill quantity ARRIVES and is discarded (`_filled` param);
   rows closed as 'cancelled' are permanently uncorrectable
   (recordLateExitFill requires exit_reason='manual'); P&L uses planned
   quantity (currently masked by the all-or-nothing gating — the manual-exit
   path CAN fabricate P&L when DB and broker drift); bracket exit legs stay
   FULL-SIZE on a partial entry (reversal risk — verify TWS child-size
   adjustment setting on the live gateway). [LIVE-GATE]
8. B Exposure caps read proposal rows, not broker positions (K from
   2026-08-06 finding 6, now with verified inventory: manual TWS positions,
   unadopted orders, second accounts all invisible). Make broker snapshot
   the canonical numerator for every cap. [LIVE-GATE]
9. B DAY→overnight conversion never passes overnight vetting: no overnight
   cap, no sector cap, gap-blind sizing — disclosed honestly in the 🌙
   WhatsApp notice, enforced nowhere. Overnight cap report is advisory and
   values holdings at COST basis. Needs a fail-closed pre-bell gate (trim
   or close to fit overnight caps + earnings/macro check) or removal of
   auto-conversion. Note the earnings guard DOES already override keeps
   deterministically — the audit's "keeps every winner" is overstated (D on
   that sub-claim). [LIVE-GATE]
10. B Acceptance-time context fails open: daily ATR/EMA10/earnings/last
    price are NOT refetched at accept (noise-stop, target-reachability,
    extension, buy-now checks silently vanish for proposals created during
    an outage); quote-fetch failure permits execution; unknown sector or
    sector-resolution error skips the sector cap with only a note.
    Fail-closed re-fetch at accept. [LIVE-GATE]
11. B Microstructure gates absent: min_avg_volume advisory-only (fires only
    on LLM-self-reported volume — third sibling of 2026-08-06 finding
    "soft limits", never closed), no spread/ADV-%/borrow/SSR/halt/LULD
    check anywhere deterministic. Shorts placed with zero shortability
    check. [LIVE-GATE]
12. B Currency: EUR base NetLiq treated as USD across sizer and caps (K,
    still D-as-overstated in direction: conservative while EUR/USD > 1,
    inverts silently below parity). The reqPnL daily-loss leg is internally
    consistent; the headroom gate genuinely mixes units. One explicit
    conversion at the account boundary. [LIVE-GATE]
13. B Risk YAML unvalidated (K from 2026-08-06, still open): strings
    survive as truthy, NaN poisons caps to false, load error falls back to
    DEFAULTS with no log, missing live overrides silently inherit paper
    rules. Schema + range + cross-field check, fail loud. [LIVE-GATE, cheap]

## Backtester (verdict: outputs remain UNTRUSTED — now verified fact, was adopted precaution)

All 2026-08-06 "not independently verified" backtester claims are now
CONFIRMED at line level, plus new ones. Do not use any engine output for
live decisions until rebuilt. The complete defect list, for the rebuild:

- Same-bar look-ahead: signal from bar i's completed OHLCV, filled at bar
  i's OPEN (engine advances the simulator with the signal bar; the
  simulator's own contract says next-bar — one-line fix, big honesty diff).
  Positions can open AND stop out inside their signal bar. This plausibly
  MANUFACTURED the rejected 7.96 OOS Sharpe.
- Second look-ahead: GDELT sentiment applies the whole calendar day's
  aggregate to every intraday bar (09:35 sees 15:50 news).
- Multi-symbol sim advances with the FIRST ticker's bar only: all fills,
  stops, marks, and the terminal closeAll price every symbol off one
  symbol's OHLC. Arithmetically meaningless, not merely noisy.
- Walk-forward fits nothing on train (inert train pass, doubled runtime);
  the only real selection (calibrate-scorer) optimizes the TEST folds.
- Per-symbol metrics reuse the portfolio equity curve (constant across
  symbols); bestMonth/worstMonth hardcoded 0; breakeven counted as loss.
- Stops fill AT the stop through opening gaps (symmetrically pessimistic
  on targets, but the loss tail is where realism matters).
- Sizing is the live sizer's notional-cap branch with the risk branch
  deleted — always max size, no confidence multiplier, no min-budget
  refusal; sized off CASH (equity debited at entry), so size depends on
  open-position count and 10×5% is unreachable.
- Default 2×ATR/3×ATR = 1.5R — live gates require 2R: the strategy being
  backtested is one the live system would refuse on every proposal.
- Archive SQL date bound drops the final day (CSV path doesn't) — fold
  boundaries shift per data source; warm-up eats ~200 bars of every test
  fold; daily halt is realized-only vs starting capital; terminal closeAll
  bypasses the equity curve (headline return ≠ trade sum by construction);
  O(N²) multi-symbol loop; ZERO tests under src/backtest/.
- Scorer-weights provenance: the equal-weights RESET file makes
  `weightsSourceLabel` print "calibrated 2026-08-11" — a small integrity
  leak in the surface built to prevent one. [cheap fix]

## Scorer / discovery (rank is an attention score, not expected return — audit wording adopted)

- B VWAP accumulates across the whole 10-day window (doc contract says
  one session; mean-reversion bands ±0.3%/±1% applied to a 10-day anchor);
  worse on the engine path (useRTH:false → 16h days).
- B RVOL is a rolling 20-bar ratio including the current bar (self-damped,
  3× reads 2.6×), not time-of-day — mis-scaled exactly at the open.
- B MACD slope × fixed 500, unnormalized: binary sign test above ~$50
  stocks, saturated on daily bars.
- B Missing data scores NEUTRAL (~46/100 composite with zero history);
  no confidence/coverage field exposed.
- B MOST_ACTIVE / HOT_BY_VOLUME / TOP_TRADE_RATE hard-coded LONG
  (pre-market most-active = down-gappers scored as longs); these codes are
  also in neither gainer nor loser scan sets, so dayMovePct stays null and

## Live gate (supersedes any earlier go-live checklist ordering)

> Remediation program for everything below:
> [REMEDIATION-2026-08-20.md](REMEDIATION-2026-08-20.md).

Keep `IBKR_ALLOW_LIVE=false` until, in order:
1. Broker-confirmed order state machine (item 6) + broker-canonical
   exposure (8) + partial-fill accounting (7).
2. Overnight conversion vetting or removal (9); fail-closed acceptance
   context (10); microstructure gates (11); YAML validation (13); currency
   (12).
3. Strategy + thresholds FROZEN, then a pre-registered validation sample:
   ≥100 correctly-accounted filled trades across regimes, acceptance on
   net expectancy + profit factor + drawdown + score calibration — not
   trade count alone. The burden is positive expectancy after costs, not
   improved loss control. Score-confidence sizing stays OFF (equal
   multiplier) until score calibration demonstrates monotonicity.
4. Backtester rebuilt (or formally abandoned as a decision input) before
   any weights calibration is applied.

Most 2026-08-19 rules (buy-now, ATR stop floors, target reachability,
regime flavor, event-mover) were derived from the losing record —
post-hoc overfitting risk is real; they ride the same frozen validation,
they do not shortcut it.
